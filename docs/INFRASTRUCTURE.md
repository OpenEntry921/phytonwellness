# 인프라 전략

## 목표 구성

사용자 → Cloudflare Free(DNS/CDN/보안) → Cloudtype(정적 웹 및 필요한 API)의 구조다. `phytonwellness.co.kr` 메일은 메일플러그가 계속 담당한다. 저장소에는 소스, 전략 문서와 배포 선언만 저장하며 비밀은 저장하지 않는다.

## 배포 흐름

기능 브랜치 → 테스트 → PR → 사용자 승인 → 병합 → Cloudtype 빌드(`npm ci && npm run build`) → `dist` 서비스 → `/healthz`와 주요 경로 확인 순서다. 현재 Cloudtype 프로젝트 및 실제 배포는 설정하지 않았다.

## DNS와 HTTPS

Cloudtype 커스텀 도메인과 원본 인증서 지원을 먼저 확인하고 가능한 경우 Cloudflare SSL/TLS `Full (strict)`를 사용한다. 웹 레코드만 프록시 후보이며 메일플러그 MX, SPF, DKIM, DMARC 및 메일 호스트는 보존하고 프록시하지 않는다. DNS 변경은 사전 내보내기/백업 후 사용자 승인 아래 수행한다.

## 환경변수와 비밀

공개 사이트 URL만 `VITE_` 변수로 둘 수 있다. SMTP/API 토큰은 Cloudtype의 서버 측 비밀에만 저장하며 빌드 결과, 로그, GitHub 이슈/PR에 기록하지 않는다. 키는 최소 권한으로 발급하고 주기 및 사고 시 교체한다.

## 백업·복구·장애 대응

GitHub 태그/커밋을 배포 원본으로 삼고 마지막 정상 커밋으로 롤백 가능하게 한다. DNS 내보내기, 배포 설정, 외부 자료 원본과 버전을 별도 보관한다. 장애 시 영향 확인 → 변경 동결 → 직전 버전 롤백 → Cloudtype/Cloudflare 상태 확인 → 원인/시간/조치를 기록한다. 원본 직접 연결과 유지보수 안내 방식은 배포 전에 검토한다.

## 미확정

GitHub 원격 저장소, Cloudtype 계정/프로젝트/런타임, 도메인 소유권과 현재 DNS, 메일플러그 레코드, 모니터링 및 복구 책임자는 확인이 필요하다.
